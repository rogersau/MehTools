# Native offline WARDOGS scanner

Caller interface (JamesTools.Core.Scanning): construct `FfmpegTesseractFrames(ffmpegPath, ffprobePath, tesseractPath)`, inject into `WardogsScanner`, then await `ScanAsync(absoluteLocalVideo, options, progress, cancellationToken)`. Work is dispatched off the caller thread. Exceptions indicate invalid arguments, inaccessible sources/tools, malformed media/OCR, resource limits, process failure/timeout, or cancellation; no partial result is returned. Callers should marshal progress with `Progress<WardogsProgress>` where appropriate. Saved review and exports are described below.

Results contain detector version, preset label, immutable options, duration and candidates (stable scan-local ID, kind, first observed source-relative seconds, latest text/position, maximum OCR confidence divided by 100, observation count). Confidence measures OCR evidence, not gameplay correctness. Times are approximate: requested source-relative sample targets, not wall-clock or exact event onset/decoded frame PTS. VFR and low frame rates add uncertainty. Interval planning is pure: `WardogsIntervals.Plan(selected, duration, pre:10, post:5, mergeGap:0)` clamps and merges windows without touching media.

## Evidence and assumptions

Prior static inspection of the packaged Python 3.15 application recovered strings establishing top-right HUD OCR, HEAD SHOT KILL / KILL ASSIST / KILL matching, persistent-row suppression, FFmpeg crop/scale, sampling/difference/OCR interval settings and Tesseract sparse-text mode (`--psm 11`). This task did not execute the scanner or embedded scripts, unmarshal code objects, or recover original source/default thresholds. No parity claim is made. The packaged README explicitly describes 10-second pre/5-second post editor markers and overlapping/nearby window merging.

The native preset is an unverified starting point: normalized crop x=.65,y=0,width=.35,height=.35; 2 samples/sec; 2 observations to confirm; retire after 3 missing samples; 960-pixel bounding square; minimum OCR confidence 35/100; row tolerance .035 of crop height. All need calibration on consented labelled recordings. No visual gating is used: every scheduled sample reaches OCR so unchanged images still confirm candidates.

## Implementation and limits

Explicit absolute executable paths are required. Supply local FFmpeg/ffprobe and Tesseract with English trained data configured in its normal installation/environment. Nothing searches temp, Downloads or the packaged app. No Python/OpenCV, network, downloads or bundled binaries are needed. FFmpeg seeks accurately to each target, extracts the first primary video frame, crops coded orientation (autorotation disabled), and scales into a bounded square. Nonstandard rotation/HUD layouts require caller crop adjustment. Tesseract TSV words are grouped vertically into rows; sparse text layout and columns can still produce wrong grouping.

Parsing and temporal tracking are separate. Named identities remove event phrases/punctuation, allowing headshot refinement and row shifts. Per-frame one-to-one matches preserve multiple adjacent rows; bare messages require positional proximity. Missing samples tolerate flicker; retired rows may generate a new candidate on reappearance. This is inherently ambiguous: indistinguishable repeated messages occupying the same position without disappearance can be suppressed; shifting bare rows can be counted again; identical player/text rows crossing positions cannot be reliably assigned; OCR identity changes may duplicate a candidate. Short-lived notifications between samples and unconfirmed single observations are missed. False positive text is possible. Candidates require human review.

Each scan holds a Windows read-only share lock against source modification/deletion through probing and scanning. Two scans globally, one extraction/OCR process at a time per scan, no frame queue. Each process has a timeout (default 30s, probe 20s), capped stdout/stderr via existing MediaTools runner, argument-list invocation and cancellation process-tree termination. One PNG is retained at a time; its private scratch directory is removed on success/failure/cancel. Filesystem cleanup failures propagate. MediaTools is unchanged. A maximum of 100,000 samples and 10,000 candidates defaults to explicit failure rather than silent truncation. Options bound sampling .1–10 FPS, image width 64–2048, confirmation 1–20, missing samples 1–100, sample cap up to 1,000,000 and candidate cap up to 100,000. Track state is bounded by 256 OCR rows per sample times missing-sample retention. Text is bounded per accepted row, process output at 64 KiB; oversized OCR output fails. Progress is per sample; callers should avoid queuing expensive callbacks.

## Validation strategy

`WardogsTests` uses labelled synthetic positive/negative OCR sequences and a fake frame adapter over a placeholder local file. Tests cover classifications/refinement, persistent rows, nearby events, movement, flicker, duplicates, reappearance, options, bounded scheduling, cancellation/failure cleanup, interval planning and TSV parsing, including word order across OCR blocks and differing glyph heights. They are deterministic logic validation, not real-game precision/recall validation. Regular tests do not require third-party tools.

Opt-in production validation: `dotnet run --project tests/JamesTools.Tests -c Release -- --wardogs-integration <absolute-tesseract.exe-path>` uses FFmpeg/ffprobe on PATH, Windows Arial, and the explicitly selected OCR tool to generate and scan a synthetic HUD recording. It checks headshot/assist classification, persistent-row suppression, approximate timestamps, an audio tail and the unchanged source hash. Successful FFmpeg extraction with no video frame supplies no OCR evidence (for example, an audio tail or a target beyond the final low-rate frame); extraction failures still abort the scan. These checks do not measure accuracy on WARDOGS gameplay.

## Saved scan review workflow

In Recording, choose **WARDOGS review…**, browse the FFmpeg folder (or leave it blank for the existing resolver), and explicitly browse to Tesseract. Tesseract must have English traineddata configured; tool failures retain a bounded error on the failed job. Advanced sampling exposes FPS, minimum OCR confidence and normalized X,Y,width,height HUD crop, with reset defaults. Preferences persist when files are enqueued. The default preset remains unverified against real gameplay.

Add explicit video files with the picker or drop files onto the window; folders are never crawled. Standalone files stay unassigned. Sessions → select a recording/clip → **Scan selected video…** pins that session ID. A single app window processes at most 20 queued/running files sequentially. Each entry snapshots tools, sampling and ownership. Cancel current and cancel pending are separate actions. Closing cancels and drains work; restart marks queued/running records Interrupted and never resumes automatically. Rescan selected creates a new record using current advanced settings and the original pinned ownership.

Select a completed scan to review its virtualized candidate table. Confidence is OCR confidence, not event accuracy. Decisions default to Unreviewed; edit decision/label or select rows and apply Keep/Reject/Unreviewed. Decisions save on cell edits and scan switches; use **Save decisions / labels / intervals** after editing pre/post/merge gap. Counts describe detected guesses. The bounded text preview shows the first 100 merged windows for KEEP candidates only. Export Montage, CSV or SRT uses KEEP candidates only. Remove saved scan removes metadata only; cancel/finish active jobs first.

**Verify source and open selected timestamp** hashes the source asynchronously before opening the existing codec-dependent player. Missing or changed sources retain their saved evidence and decisions, but cannot open through this action; explicitly rescan. Verification uses SHA256, length and UTC write time. A read lock spans initial fingerprinting and the entire scan. Reopening from scanner review holds a read lock continuously across verification and transfer to the player; that player retains a read lock until closed. The shared player uses the scan's saved FFmpeg folder and retains the original session ownership.

`wardogs-reviews.json` lives in the settings directory. Schema 1 stores up to 200 records / 32 MiB, bounded candidate text, errors and labels. Writes serialize and atomically replace with `.bak`; valid backup recovery preserves corrupt primary as `.corrupt-<id>` and displays a notice. A missing primary also recovers from a valid backup. Read-only reopening and unchanged decisions do not rotate backups. Without a valid recovery source, opening fails visibly and preserves files. Incomplete jobs publish no candidate results. Sources are never modified. Preferences are owned by this library rather than AppSettings. Review saves are guarded against stale UI selections, and shutdown waits for additions and scanning to settle; a save failure keeps the window open with an error.

Module interfaces: `WardogsReviewStore(directory, IWardogsScanWork)` exposes `InitializeAsync`, deep `SnapshotAsync`, `EnqueueAsync`, serialized `RunAsync`, `CancelPendingAsync`, `ReviewAsync`, `SourceMatchesAsync`, and `RemoveAsync`. `NativeWardogsScanWork` is the production adapter; tests supply a fake scan adapter with real temporary-file hashing. `SavedWardogsScan` contains immutable detected `Result`, separate `Reviews` keyed by candidate ID, pinned nullable `SessionId`, fingerprint/status/timestamps/preferences, and pre/post/merge gap. `Intervals()` calls `WardogsIntervals.Plan` for KEEP candidates only. The exporter consumes a deep completed snapshot, verifies source bytes, and preserves pinned ownership. `WardogsReviewWindow(directory, toolsFolder, Action<string,TimeSpan,Guid?,string> playback, Action<WardogsPublishedExport>? published)` owns presentation, with `AddFilesAsync(paths, sessionId)` and awaited `Task<bool> ShutdownAsync()` (false means saving could not complete); MainWindow provides the existing player callback and drains shutdown before application exit.

`WardogsReviewTests` exercises roundtrip/deep snapshots, pinned ownership, decision/interval restart, changed-source detection, queued interruption, active/pending cancellation, invalid decision metadata, backup recovery and refusal to silently reset corruption. The review window was rendered in isolation with synthetic rows at normal and minimum dimensions; the main application and automation were not launched. No real recording was scanned. Interactive playback and hardware behavior remain untested. Playback availability still depends on installed codecs. Real-game accuracy remains unvalidated.

## Verified exports

Export saves current edits first; invalid edits abort visibly. Choose a new local MKV, CSV or SRT destination. One export runs at a time; Cancel export cancels it and Clear export result clears its message. Closing cancels and awaits exports and selected-candidate thumbnails. A fresh source fingerprint check holds a continuous read lock through publication for every format. Changed, missing or unreadable sources require a rescan. Private destination-folder staging is cleaned on failure/cancellation. Publication never overwrites, including races. A cleanup failure after publication is reported as a warning alongside the successful output; it does not prevent session attachment.

Montage copies first primary video and ALL audio into MKV. No MP4/transcoding mode is offered. Up to 200 merged KEEP windows use saved pre/post/merge settings (defaults 10 seconds before, 5 after). Ordered codecs, audio sample parameters, time bases and extradata hashes are checked. Remux time-base changes relative to source are allowed; segments must match each other. Final streams, duration and packet readability are verified. Segment duration deviations above 10 seconds are refused; final duration must match summed verified segments within 0.5 seconds. Requested and verified durations are shown separately. Keyframe cuts can include extra material; no frame accuracy or HDR fidelity guarantee. See [FFmpeg concat documentation](https://ffmpeg.org/ffmpeg-formats.html#concat).

CSV lists approximate source seconds/type/label/OCR evidence/confidence and padded range with invariant numbers, quoted fields and formula-prefix protection. SRT uses independently padded source windows, deterministic order and a START OF RECORDING cue at zero; overlapping cues are possible. Controls/newlines and angle markup in labels are normalized. Text exports are never attached as videos.

`WardogsExporter(MediaTools).ExportAsync(snapshot, destination, kind, progress, token)` returns `WardogsPublishedExport` with path, captured nullable session ID, requested seconds, verified montage seconds and an optional cleanup warning. `Capture` copies candidate/review arrays. The UI pins current completed review settings, tools and session ownership before background work. Only verified published montages reach the session callback. Attachment failure is reported separately and leaves the published file available for manual attachment. Unassigned input produces an unassigned clip.

Candidate selection generates one cancellable timestamp thumbnail after source verification; missing tools/codecs leave saved text usable. A read lock is retained while previewing the selected scan, so switching candidates does not repeatedly hash a large recording. Changing scans or closing releases the lock after pending thumbnail work finishes. No per-row thumbnails run. Explicitly select Tesseract with English traineddata; binaries are never bundled or installed.

Opt-in check: `dotnet run --project tests/JamesTools.Tests -c Release -- --wardogs-montage-integration`. Generates H264/two AAC tracks and two disjoint windows; checks hash, stream validation, full fixture decoding, sane duration, no overwrite and cancellation cleanup. The local run requested 4 seconds and verified 6.44 seconds. It does not validate gameplay accuracy; isolated WPF layout rendering is checked separately.
