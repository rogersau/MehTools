# Opt-in live WARDOGS

Nothing starts automatically. In **Recording → Live WARDOGS**, choose the game executable, refresh matching windows and select an explicit HWND. Choose a trusted architecture-matching Tesseract 5 DLL and a folder containing `eng.traineddata`. Enter rate (.25–4 Hz), soft duty budget (.01–1), and normalized crop coordinates. Save configuration separately; Start is required for every run, including after reopening. Save never enables capture. Opening or enumerating windows does not start capture or the worker.

Press **Start**, then focus the selected game. Only that foreground, non-minimized window is sampled. Stop and window/app shutdown cancel initialization or processing and await helper termination and source disposal. Errors stop the run; correct the configuration and explicitly Start again. History and totals reset on each Start. No raw frames or OCR text are logged or persisted, and no automatic clip/bookmark, Steam, OBS, cash or death actions occur.

Capture uses Windows.Graphics.Capture `CreateForWindow`, with no desktop/GDI fallback, injection or process-memory access. Identity is pinned to HWND, PID, process start time and executable path. Target loss stops; replacement processes/windows require selection and Start. A 100 ms focus check closes capture resources on focus loss/minimize; resume within the active run opens a fresh capture and baseline. Dimensions are physical captured pixels, independent of WPF DPI. Resize recreates capture and resets baseline. Run-relative QPC frame timestamps increase across epochs. A two-buffer free-threaded GPU pool is drained at sampling cadence; only the normalized ROI is copied to a staging texture before CPU grayscale conversion. CPU reads occur only when the detector samples, never for every display refresh. Readback crop is capped at 4,194,304 pixels (16 MiB BGRA); larger crops fail clearly. GPU readback uses [nonblocking Map](https://learn.microsoft.com/en-us/windows/win32/api/d3d11/nf-d3d11-id3d11devicecontext-map), cancellation checks and a 250 ms readiness deadline; a timeout stops the run. This bounds readiness polling, not all graphics-driver calls or GPU capture overhead. Output is downsampled to at most 1024 × 512. No crop preview is currently provided.

The default crop is the unverified own-reward region (1350,45,550,240 at 1920×1080). Adjust it for game resolution/UI scale; exclude the left-side global other-player feed and cash. Own-HUD rewards such as supplies deposited, vehicle refuelling, control zone and passenger survival are not kill evidence. Baseline suppression deliberately ignores notifications visible when capture starts/resumes. Short notifications, pacing, missed OCR and crop errors can miss events. No real positive kill has been validated locally.

Requires Windows 10 build 19041 or later and supported graphics hardware/session. Capture permission restrictions, protected windows, anti-cheat policy, exclusive fullscreen and remote sessions may prevent capture or yield blank content. Use supported windowed/borderless SDR play. HDR is not tone-mapped by this BGRA path and can reduce OCR quality. No bypass is attempted. See Microsoft's [capture guide](https://learn.microsoft.com/en-us/windows/apps/develop/media-authoring-processing/screen-capture) and [CreateForWindow contract](https://learn.microsoft.com/en-us/windows/win32/api/windows.graphics.capture.interop/nf-windows-graphics-capture-interop-igraphicscaptureiteminterop-createforwindow).

The window displays paused/running/throttled/error status, per-run totals and at most 256 timestamped events. UI snapshots occupy one replaceable slot, consumed at 4 Hz with generation guards. Processing milliseconds exclude capture age; worker CPU is percent of **one core**, separate from whole-app/game CPU. Soft pacing is not a hard quota. To assess cost, explicitly compare otherwise identical Performance monitor sessions with this detector off/on. There is no FPS impact claim or automatic PresentMon launch.


## Caller interface for task21

Create `PersistentHudOcr` explicitly with `StartAsync(absoluteHelperExe, absoluteTesseractDll, absoluteTessdataDirectory, token)`, then construct `LiveWardogsDetector(ILatestHudFrameSource, IHudOcr, LiveWardogsOptions?, TimeProvider?)`. Await `RunAsync(Action<LiveWardogsSnapshot>, token)`. Cancel and await that task to Stop. A run owns/disposes its OCR adapter on cancellation, failure or callback exception. Construct a fresh adapter/detector for another run. Callbacks execute on the loop thread; marshal snapshots to WPF yourself. Errors propagate; there is no automatic restart.

`ILatestHudFrameSource.LatestAsync(token)` returns null or one latest `HudFrame(Source, Epoch, Timestamp, Width, Height, Stride, Gray)`. No queue: replace older captured buffers. The source must honor cancellation, return promptly, and transfer a stable buffer that nobody mutates while processing. Timestamp is monotonic elapsed time within the source run, continuing across epochs. Increment Epoch on target, crop, original resolution, pause/resume or timestamp-origin changes; Source identifies the selected target. Equal/older timestamps within an epoch are ignored. Gaps over four seconds and cropped dimension/stride changes establish a fresh baseline. A source must advance epoch after a pause even if its own timestamps paused too. The detector intentionally trusts that source contract; it does not capture or infer target identity itself.

Supply already cropped/resized 8-bit grayscale: width 16..1024, height 16..512, stride width..2048, exact stride*height bytes (maximum 1 MiB). Starting unverified 1080p ROI: x1350 y45 width550 height240, excluding money fields and the global feed. Capture must bound its own buffers before allocation.

Snapshots contain immutable bounded history (256 events), lifetime run totals (`Kills`, `Headshots`, `Assists`), sample/OCR rates since run start, stale/unchanged skips, last OCR latency and processing latency (source read through tracking, excluding pacing and source capture age), throttled flag, worker CPU milliseconds and loop elapsed seconds. Worker CPU/1000 divided by loop elapsed is one-core worker CPU utilization, not total machine utilization or whole-app/game cost. CPU before the detector run is excluded. Fake adapters default to zero CPU. Events use their first observed timestamp and stable IDs: update existing IDs on headshot refinement instead of counting another kill. Headshots are a subset of kills; assists are separate. Lifetime totals survive history eviction. Active tracks cap at 256; extra rows are ignored. Two observations confirm, three OCR absences remove a row. Initial/reset rows remain baseline until disappearance; history persists across source resets. Names/OCR strings are not included in output history.

Default 2 Hz, configurable .25..4 Hz. Exactly one operation runs at once. Exact pixel equality can skip OCR unless confirmation or disappearance is pending; recheck every two source seconds. Moving backgrounds defeat this gate. Processing wall time / soft duty budget determines adaptive delay (default 25%), with minimum sampling interval and cancellation-aware waits. This is pacing, not a hard CPU quota. Delays, gating, OCR errors and short notifications can cause missed events. Dependencies must honor their cancellation contract; the production OCR adapter enforces termination independently of native cooperation.

## Worker deployment

Build `src/JamesTools.OcrWorker/JamesTools.OcrWorker.csproj` Release. Current framework-dependent helper is `src/JamesTools.OcrWorker/bin/Release/net10.0-windows/JamesTools.OcrWorker.exe`, alongside its dll, deps.json, runtimeconfig.json and JamesTools.Core.dll. Requires Windows and .NET 10 runtime. Ordinary app builds copy the helper and its top-level runtime files into `tools/ocr`. App publish separately publishes the worker to `tools/ocr` with the same runtime identifier and self-contained setting. Self-contained win-x64 packages include the worker runtime and require no separate .NET installation. Existing package ZIP and recursive installer include this folder. Native Tesseract and English tessdata remain explicit external dependencies and are never bundled or auto-discovered. Supply a trusted, architecture-matching Tesseract 5 DLL, all its native dependencies beside it (or System32), and explicit tessdata containing eng.traineddata. Architecture mismatch fails at Windows load; missing C exports/version/model fail startup. No PATH/private-folder discovery or installation exists. The locally tested DLL identifies as v5.5.3.20260724, x64 on this machine.

LoadLibraryEx uses DLL-directory plus System32 search flags. Worker-local OpenMP environment limits both thread variables to 1; below-normal process priority is best effort. Native handles, engine and returned TSV pointers are freed on normal exit. Forced termination lets Windows reclaim them on stuck/crashed OCR. The parent kills/reaps its process on deadline, cancellation or disposal; startup deadline defaults to 10s and request deadline 3s. No restart loop. stderr is continuously drained, retaining at most 2 KiB for failure diagnostics; do not persist these potentially sensitive native diagnostics. stdout is exclusively length-prefixed UTF-8 JSON, capped at 1,500,000 bytes before payload allocation. Requests are serialized; image dimensions, stride, TSV text (64 KiB), response rows (256) and row text are bounded. A semaphore prevents concurrent native requests.

C API signatures and lifecycle were checked against the [official capi.h](https://github.com/tesseract-ocr/tesseract/blob/main/include/tesseract/capi.h), [API examples](https://tesseract-ocr.github.io/tessdoc/APIExample.html) and [FAQ](https://tesseract-ocr.github.io/tessdoc/FAQ). Native GetTsvText has no CLI TSV header: the helper adds one before reusing the offline TSV geometry/parser. Offline scanner interfaces remain unchanged.

Startup and request deadlines throw `TimeoutException`; explicit caller cancellation remains cancellation. Cleanup waits are bounded, concurrent disposal shares one cleanup operation, and malformed worker replies fail the run. The caller must surface failures and await cleanup before permitting another run.

## Validation and replay

`dotnet build JamesTools.sln -c Release`

`dotnet run --project tests/JamesTools.Tests -c Release --no-build`

Regular tests use synthetic rows/buffers, an auto-advancing fake monotonic clock and an owned fake worker process; no native libraries, FFmpeg, recordings or D: access. They cover baseline, confirmation, refinement, persistence, assists, disappearance, epoch/resolution/gap reset, repeated frames, unchanged gating, bounded input/protocol, failure, timeout and cleanup. The production native check is opt-in:

`dotnet run --project tests/JamesTools.Tests -c Release --no-build -- --live-replay <absolute-helper.exe> <absolute-libtesseract-5.dll> <absolute-tessdata-directory> <550x240-gray-file> [more-gray-files]`

Inputs are exact 132000-byte raw grayscale ROI frames, read in supplied order. The command measures direct persistent-engine OCR first, then passes the same images (each twice, preceded by a synthetic blank baseline) through the actual detector with virtual pacing. It reports per-call times and direct replay wall/CPU/throughput separately from startup. Virtual-clock loop replay does not measure real-time pacing. FFmpeg may prepare bounded raw replay inputs outside the live path. Standard tests never decode media.

Local run: four 550x240 inputs (one synthetic HEADSHOT KILL label and three recorded crops at 300,301,302 seconds). Startup 232.6ms; direct OCR calls 53.9,9.1,2.3,39.4ms, wall107.7ms, worker CPU78.125ms excluding startup; throughput37.2 inputs/s. The first call includes first-request/JIT overhead; three subsequent calls are warmed but contain different content, so this is not a latency distribution. The same-engine loop processed nine samples, six OCR calls and emitted exactly one Headshot event for the synthetic positive. CPU/wall is roughly 0.73 one core over this tiny direct batch; it is not game or whole-app impact. No game FPS measurement was made.

The inspected full frame at300s is a negative own-kill example. The301/302s crops are unlabelled; all three yielded no KILL OCR strings. No real positive has been found or validated. Existing sparse sampling is not labelled accuracy evidence. Recorded inputs, images and local metrics remain ignored under artifacts/wardogs-live-calibration; never upload or add them as fixtures. These results establish local replay execution only, not real-game precision/recall or CPU guarantees.
